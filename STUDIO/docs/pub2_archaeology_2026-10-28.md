# pub2 → pub4 restoration audit — 2026-10-28

## Decision

Do **not** merge or copy `pub2` wholesale. It is a historical monorepo/scrapbook, not a coherent snapshot that can be overlaid safely. The reviewed `main` tree has 279 entries / 252 blobs / about 148.4 MB; most of the size is media, images and an embedded PDF, not missing runtime code. The current `pub4` tree already has newer, distinct owners for MASTER, RAILS, OPENBSD and STUDIO.

This report is a repository-wide inventory and architecture comparison with detailed inspection of the key status/architecture documents, legacy AI and media components, app READMEs, OpenBSD reports, playlist prototype and current owner paths. It is **not** a line-by-line audit of every binary/media object or every unreachable Git object. The latest 100 commits, path-specific history for Postpro/Repligen, and all three visible non-main branch tips were checked. Runtime tests and production probes were not run for this report.

- `pub2/main`: `ad05242c97fff1b01450434974aad628d7de8628` (2026-05-07)
- `pub4/main` at the start of this audit: `c3ce5a4023c189bf884c3cc74a22768ac9c36658`
- Three Copilot branches remain divergent from pub2 main: canonicalization is 2 ahead / 2 behind and includes backup/config deletions; the two index.html fix branches are 3 ahead / 25 behind and 2 ahead / 8 behind. They are not safe candidates for an unreviewed merge.

## What should actually be carried forward

1. **Radio visualizer parity check (priority candidate).** Verify whether the current Brgen Radio renderer has equivalents for the old seven modes, six themes, auto-switch-on-track-change and mobile tilt. Existing current owners make a careful feature comparison more useful than a standalone HTML import.
2. **Explicit legacy product disposition.** Record BAIBL, Blognet, Hjerterom and Privcam as archived / folded into Brgen / owner-approved future work. The docs are useful for extracting requirements later, not sufficient authorization to add four new apps.
3. **Behaviour-level AI gap audit.** Use AI3/Aight for concepts and provenance; only testable deltas beyond the current MASTER owners survive. This is gated on the full-MASTER read.
4. **Named media-data delta only.** The current Dilla dataset already carries the old chord vocabulary. Inspect distinct records and source notes—not filenames, duplicated audio or raw array contents—before deciding that any musical idea was lost.
5. **Operational history as evidence, not truth.** Keep old OpenBSD failures and deployment reports linked for archaeology; obtain fresh host/HTTP/DNS evidence before promoting any claim to current status.
6. **Retire obsolete paths deliberately.** The stale Copilot branches in pub2 are divergent and make changes that include old backup removal or only touch `index.html`; neither is a clean restoration branch. Do not merge them into pub4.
